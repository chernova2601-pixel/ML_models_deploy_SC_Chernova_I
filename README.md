## Описание проекта
Веб-сервис для прогнозирования дефолта по кредитным картам. 
Проект демонстрирует полный цикл внедрения ML-модели: от обучения до контейнеризации и A/B-тестирования.
Модель машинного обучения (Random Forest) обучена на датасете UCI «Default of Credit Card Clients».  
Цель — предсказать, допустит ли клиент дефолт в следующем месяце.
### Архитектура и обоснование
Проект реализован как **монолитное приложение** на базе веб-фреймворка Flask. Такой архитектурный стиль выбран из-за:
- простота и целостность. Сервис решает одну узкую задачу и не содержит логически независимых компонентов, которые требовалось бы разрабатывать, версионировать и развертывать отдельно. Модель, предобработка и API-слой тесно связаны и используют общие структуры данных, что делает монолит естественным способом организации кода.
- ускорение разработки и тестирования. Единое приложение легче запускать локально, отлаживать, писать сквозные (end‑to‑end) тесты и поддерживать.
- минимальная потребность в горизонтальном масштабировании. В гипотетической рабочей нагрузки отдела кредитного скоринга ожидаемый поток запросов не требует разделения обработки предсказаний, логирования и администрирования на разные сервисы.
При гипотетическом росте нагрузки (например, десятки тысяч одновременных запросов на предсказание или появлении требования асинхронной обработки батчей) монолит можно эволюционировать.
В этом случае целесообразно внедрить брокер сообщений (например, RabbitMQ).
Он позволит:
* принимать запросы на предсказание в очередь и немедленно возвращать клиенту идентификатор задачи (асинхронный паттерн);
* организовать несколько воркеров, которые будут забирать задачи из очереди, выполнять ресурсоёмкие предсказания и складывать результаты в другую очередь;
* централизованно собирать логи и метрики через отдельный сервис-потребитель, разгружая основной API.
Логирование и мониторинг
Логи в формате JSON выводятся в stdout. В production-среде их можно собирать в ELK-стек (Elasticsearch, Logstash, Kibana) для централизованного мониторинга и анализа. 

### MLOps инструменты
#### DVC (Data Version Control)
DVC предназначен для контроля версий наборов данных и артефактов моделей, работая поверх Git. Он позволяет:
- Хранить большие файлы (например, исходный датасет `UCI_Credit_Card.csv`) в удалённом хранилище (S3, GCS, локальный сервер) и фиксировать их хэши в Git-репозитории.
- Воспроизводить конвейеры обработки данных и обучения: одна команда `dvc repro` перезапускает только те шаги, которые зависят от изменившихся данных или кода.
- Легко возвращаться к любой версии датасета или модели, что критично при аудите или откате.
В контексте данной модели DVC позволил бы зафиксировать исходный датасет и отслеживать изменения в процессе предобработки, а также управлять версией обученной модели (`model_v1.pkl`).
#### MLflow
MLflow — платформа для управления жизненным циклом машинного обучения, включающая три основных компонента:
- *MLflow Tracking* — логирование параметров обучения (гиперпараметры RandomForest: `n_estimators`, `max_depth` и т.д.), метрик (F1-score) и артефактов (модель, графики). Это позволяет сравнивать эксперименты и выбирать лучшую модель.
- *MLflow Projects* — упаковка кода и зависимостей в воспроизводимые единицы.
- *MLflow Models* — унифицированный формат для развёртывания моделей в различных средах (Docker, REST API, Spark).
Для данного проекта MLflow мог бы использоваться для записи каждого эксперимента по настройке гиперпараметров, сохранения метрик на тестовой выборке и автоматической регистрации лучшей модели в реестре моделей. Это дало бы возможность проследить, как изменение параметров влияет на итоговый F1-score.

Таким образом, внедрение DVC и MLflow превращает разовую модель в поддерживаемую, воспроизводимую и управляемую систему — важный шаг для реальных MLOps-процессов.

### Бизнес-метрики
#### 1. Ожидаемые потери от дефолтов (Expected Loss, EL)
EL = PD × EAD × LGD, где:
- PD — предсказанная моделью вероятность дефолта;
- EAD — сумма задолженности клиента на момент дефолта (известна из данных);
- LGD — доля потерь при дефолте (константа, например 0,6).
Модель позволяет отсеивать заявки с высоким PD, снижая ожидаемые потери по портфелю. **Расчёт:** для каждого одобренного кредита умножаем PD на EAD и LGD, суммируем. Чем ниже суммарный EL при фиксированном уровне одобрения, тем лучше модель.
#### 2. Коэффициент одобрения при фиксированном уровне дефолта (Approval Rate)
Банк хочет выдавать кредиты как можно большему числу клиентов, но при этом доля невозвратов среди получивших кредит не должна превышать допустимый порог (например, 5%). Модель оценивает риск каждого клиента. Чем точнее модель, тем больше клиентов можно одобрить, оставаясь в рамках риск-лимита.
**Формула:**
`Коэффициент одобрения = (количество одобренных заявок) / (общее количество заявок)`
1. Упорядочить всех клиентов по предсказанному риску – от самого надёжного (минимальная вероятность дефолта) до самого рискованного (максимальная вероятность).
2. «Одобрять» кредиты по очереди, начиная с самого надёжного, и считайть долю реальных дефолтов среди уже одобренных. Остановиться, как только доля дефолтов превысит целевой порог (например, 5%).
3. Посчитайть, какая доля от всех заявок была одобрена.

**Что даёт метрика:**  
Чем выше Approval Rate, тем большую долю заявок можно одобрить, не превышая заданный уровень дефолта.

## Быстрый старт

### Локально (Python 3.11+)
1. Клонируйте репозиторий и перейдите в него:
   ```bash
   git clone https://github.com/chernova2601-pixel/ML_models_deploy_SC_Chernova_I.git
   cd ML_models_deploy_SC_Chernova_I
   ```
2. Создайте и активируйте виртуальное окружение:
```bash   
python -m venv venv
source venv/bin/activate
```
3. Установите зависимости:
```bash
pip install -r requirements.txt
```
4. Запустите сервер:
```bash
python app/api.py
```
Сервер запустится на http://localhost:5000

5. Проверьте работоспособность (в другом терминале):
```bash
curl http://localhost:5000/health
curl -X POST http://localhost:5000/predict \
     -H "Content-Type: application/json" \
     -d '{"features": [1]*23}'
```
6. После окончания работ - остановка сервера: нажмите Ctrl+C

### Docker Compose
Файл docker-compose.yml запускает два сервиса:
Ml-service – наш ML-сервис (порт 5000).
logger – простой сервер Nginx для имитации сбора логов (порт 8080).
Запуск всех сервисов:
```bash
docker-compose up -d
```
Проверка:
```bash
curl http://localhost:5000/health          # ML-сервис
curl http://localhost:8080                 # Nginx (логгер)
```
Остановка:
```bash
docker-compose down
```
